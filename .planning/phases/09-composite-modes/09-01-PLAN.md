<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config file → in-memory Config | Untrusted TOML values (user-supplied); transforms must not re-read from disk |
| CLI flag → ConfigTransform selector | Mode flag determines which transform applies; only two valid transforms exist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01-01 | Tampering | ApplyZenProfile/ApplyDeepProfile | mitigate | Functions are pure (no I/O, no exec); applied only inside BootReconApp after config.Load; cannot be bypassed by user config because transforms run after Load and before Boot (D-03) |
| T-09-01-02 | Information Disclosure | ConfigTransform func field | accept | Field is a function pointer set by CLI code, not from external input; no user-controlled function pointer injection possible |
| T-09-01-03 | Elevation of Privilege | zen passive guarantee | mitigate | ApplyZenProfile explicitly sets Vulns.Enabled=false and Subdomains.Brute.Enabled=false; these fields are checked by tasks at Run() time; even if file config enables vulns, zen transform wins (D-03) |
| T-09-01-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan; pure Go stdlib + internal packages only |
</threat_model>
