## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| subdomains list → s3scanner subprocess | Subdomain list derived from artefacts/subdomains.jsonl (scope-filtered at write time) used as s3scanner bucket input |
| asnmap API key → log | PDCP API key must pass through redactor before any log output |
| dnstake JSON output → findings.jsonl | Tool JSON output parsed and written through OutputTree scope filter |
| Zone transfer AXFR response → subdomains.jsonl | dig AXFR output parsed and scope-filtered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-14 | Information Disclosure | PDCP_API_KEY in asnmap invocation | mitigate | Key passed via env var to asnmap subprocess (not as a CLI arg) using Backend.Exec env injection if supported, or via config file; register key as redacted secret before any Tool.Run log |
| T-04-15 | SSRF | Zone transfer AXFR to arbitrary NS server | mitigate | NS servers are discovered via DNS resolution of the target domain (authoritative NS records); they are not user-supplied at scan time. AllowTransfer=false is the default (SUBD-10 gate) |
| T-04-16 | Elevation of Privilege | s3scanner finding public buckets | accept | s3scanner is doing what it's designed to — find misconfigured cloud storage; bucket access is read-only discovery; BucketRecord.Access field accurately reflects findability |
| T-04-17 | Injection | s3scanner bucket name from subdomains | mitigate | bucket input file path constructed from cfg (not user input); subdomains in file already scope-filtered at Tree.Append boundary; s3scanner receives a file path not inline data |
| T-04-SC | Tampering | dig system tool invocation | mitigate | dig is in tools.lock as kind="system" (added in this plan's action); Runner.Run verifies binary path at Registry.Lookup; no shell interpolation |
</threat_model>
