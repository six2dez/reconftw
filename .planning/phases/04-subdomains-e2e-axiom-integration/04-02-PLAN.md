## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Task args → puredns/dnsx subprocess | Wordlist path, resolver file path, domain, rate-limit integers derived from config — cross into subprocess args |
| puredns/dnsx stdout → app.Tree.Append | Tool output (resolved subdomains) crosses scope filter boundary |
| Resolver file path → disk read | Config-supplied resolver file path read at health-check time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Injection | SubBruteTask puredns args | mitigate | domain from app.Target.Domain (pre-validated); wordlist path from config (not user input at scan time); integer args (wildcard limits) are strconv.Itoa — no injection surface |
| T-04-05 | Injection | Resolver file path in config | mitigate | cfg.Subdomains.Brute.ResolverFile is a config-time value validated by Config loader at startup; path traversal is a config-time risk (ARCH-02 specifies fail-fast config validation) |
| T-04-06 | DoS | Resolver health gate bypass | mitigate | If MinResolvers check is bypassed and 0 resolvers are available, puredns will exit non-zero immediately; SubBruteTask receives ToolError and Scheduler records errored — no infinite hang |
| T-04-07 | Denial of Service | puredns wildcard DNS flood | accept | puredns wildcard testing is intentional reconnaissance behavior; PUREDNS_PUBLIC_LIMIT rate caps prevent excessive third-party DNS load |
| T-04-SC | Tampering | axiom-scan module mapping in future AxiomBackend | mitigate | Tasks are backend-agnostic (no AXIOM branch); AxiomBackend's module map (plan-06) is the injection point — plan-06 validates Tool→module mapping |
</threat_model>
