<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSH known_hosts | AxiomBackend.HealthCheck reads/modifies ~/.ssh/known_hosts for hostkey repair — privilege-sensitive file |
| Fleet node → axiom-scan output | axiom-scan output is untrusted (remote fleet may return unexpected data); must pass through scope filter at OutputTree.Append |
| AxiomBackend SSH stderr → log | SSH error output may contain hostnames/IPs from fleet; must not leak internal fleet IPs to notifier |
| cfg.Axiom.* → AxiomBackend init | Fleet config (fleet name, count, resolver path) derived from TOML; validated at config load time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-18 | Tampering | AxiomBackend.repairKnownHosts modifies ~/.ssh/known_hosts | mitigate | Only removes exact offending host key (ssh-keygen -R <host>); operation is logged at Info verbosity; only runs when AutoFixHostKey=true (explicit opt-in per AXIOM-07) |
| T-04-19 | Spoofing | Malicious fleet node returning injected subdomains | mitigate | All axiom-scan output flows through OutputTree.Append scope filter — injected out-of-scope lines are rejected with *OutOfScope; TakeoverRecord/BucketRecord schemas validate structure before write |
| T-04-20 | Information Disclosure | Fleet SSH stderr leaking internal IPs in log | mitigate | AxiomBackend registers fleet node IPs as redacted secrets before logging stderr; register_secret(node_ip) pattern from XCUT-07 |
| T-04-21 | Denial of Service | FailoverBackend threshold too low causing immediate kill-switch | accept | Default Threshold=3 from cfg; user can configure higher; documented behavior is "3 consecutive axiom failures → fall back permanently for this run" — intentional safety valve |
| T-04-22 | Tampering | newSubsCmd RunE AxiomBackend Launch on every subs invocation | mitigate | cfg.Axiom.Enabled gate in RunE prevents fleet launch unless explicitly configured; --axiom flag (or cfg.Axiom.Enabled=true) is required |
</threat_model>
