<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Task.Run → app.Tools.Run | Tool name + args derived from config (subdomain domain string, token file path) cross into subprocess dispatch |
| passive Task output → app.Tree.Append | Tool stdout (subfinder/crt/github output) enters scope-filter boundary before disk write |
| GitHub/GitLab token → log/notifier | Bearer tokens in tool invocation args must never appear in log lines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Injection | SubfinderTask.Run args | mitigate | Domain arg comes from app.Target.Domain which is validated by NewTarget via validate_domain regex `^[a-zA-Z0-9.-]+$` before AppContext is built; no shell interpolation (Go slice args never shell-expanded) |
| T-04-02 | Information Disclosure | GitHub/GitLab token in log stderr | mitigate | Call `app.Log.(*log.RedactingLogger).RegisterSecret(token)` before any log call that may include tool stderr; covered by XCUT-07 redaction tests from Phase 3 |
| T-04-03 | Tampering | scope.go IsInScope on malicious subdomain output | mitigate | domainRe `^[a-zA-Z0-9.-]+$` rejects shell metacharacters; anchored matching prevents substring false positives; OutOfScope lines logged+skipped, not propagated |
| T-04-SC | Tampering | tools.lock new entries (15 Go module installs) | mitigate | Phase 4 expands the seed; Phase 11 adds SHA-256 pins. All 15 new modules are well-known projectdiscovery/gwen001/tomnomnom/hakluke packages; slopcheck-equivalent: executor must verify module paths match PATTERNS.md §Group 10 before appending |
